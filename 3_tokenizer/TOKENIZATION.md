# Правила токенизации

Токенизатор получает чистый текст в UTF-8, а не HTML. Правила одинаковы для
обычного текста и кода: синтаксический анализ C/C++ не выполняется.

## Базовый токен

Токен состоит из букв Unicode (категории L), десятичных цифр (Nd) и `_`.
Комбинируемые знаки (категории M) разрешены после начала сегмента.
Сегмент должен содержать хотя бы одну букву или цифру: одни подчёркивания
токеном не считаются. Цифра в начале допустима.

Буквы приводятся к нижнему регистру по Unicode simple lowercase mapping.
Это не case folding: например, `ß` не заменяется на `ss`.
Нормализация Unicode NFC/NFKC не выполняется. Поэтому визуально одинаковые
записи `é` и `e` + combining acute accent могут оставаться разными токенами.

Порядок токенов сохраняется. Повторы не удаляются, стоп-слова не фильтруются,
стемминг и лемматизация не выполняются.

## Технические обозначения

### Подчёркивания

Идентификатор сохраняется целиком, включая начальные и конечные `_`:

```text
pthread_create  → pthread_create
__init__        → __init__
___             → нет токенов
```

CamelCase не разбивается: `MemoryBarrier` → `memorybarrier`.

### Области имён

`::` сохраняется между двумя допустимыми сегментами:

```text
std::vector              → std::vector
std::vector::iterator    → std::vector::iterator
::malloc                 → malloc
std::                    → std
```

Шаблонные аргументы — отдельные токены:

```text
std::vector<int> → std::vector, int
```

### Обозначения с `++`

Сохраняются специальные обозначения `C++`, `G++`, `Clang++` без учёта регистра.
Сразу после `++` допускается последовательность ASCII-цифр: `C++20` — один токен.
За обозначением не должна идти буква, `_` или комбинируемый знак.
Произвольные операции инкремента не сохраняют плюсы:

```text
C++            → c++
c++20          → c++20
g++            → g++
clang++        → clang++
value++        → value
```

В строке `C++suffix` специальное обозначение не распознаётся:
результат — `c`, `suffix`. В `C++::name` результат — `c++`, `name`:
специальные обозначения не соединяются через `::`.

## Разделители

Остальные символы — разделители. В частности:

- пробельные символы и переводы строк;
- дефисы, тире и знаки минуса;
- точки, запятые, кавычки, апострофы;
- скобки, `<`, `>`, `=`, `*`, `&`, `#`;
- `/`, `\\`, одиночный `:`;
- эмодзи и другие символы, не входящие в правила выше.

Разделители не выдаются отдельными токенами.

```text
memory-mapped             → memory, mapped
#include <sys/types.h>    → include, sys, types, h
obj.member                → obj, member
ptr->field                → ptr, field
-O2                       → o2
can't                     → can, t
```

Пути, URL и имена файлов не сохраняются целиком. Числа не преобразуются:
`0xFF` → `0xff`, а `6.12` → `6`, `12`. Знак минуса не является частью числа.

## Ошибки и статистика

Некорректная UTF-8 последовательность — ошибка входа, а не повод молча
удалить байты. Токенизатор должен завершиться с ненулевым кодом и диагностикой
в stderr.

Длина токена измеряется в Unicode code points, включая сохранённые `_`, `:`
и `+`. Это не число байтов и не число визуальных символов.
Средняя длина — сумма длин всех вхождений / количество вхождений.
Для пустого текста количество и средняя длина равны 0.
Объём входа для измерения скорости считается отдельно, в байтах UTF-8.

## Ограничения

- `Foo` и `foo` объединяются, хотя в C/C++ это разные идентификаторы.
- CamelCase не даёт отдельных терминов, дефисные слова, наоборот, разбиваются.
- `std::vector` и `vector` — разные токены; поиск по неквалифицированному имени
  потребует дополнительного правила на более позднем этапе.
- Операторы C++, пути и версии теряют часть структуры.
- Апострофы разбивают английские сокращения.
- Отсутствие Unicode-нормализации может разделять эквивалентные написания.

Это осознанный первый вариант, а не полноценный парсер программного кода.
