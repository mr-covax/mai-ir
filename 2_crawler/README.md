# Crawler

Асинхронный сборщик документации по низкоуровневому программированию.
Python 3.12+, uv, MongoDB 8.0 (replica set), Docker Compose.

## Запуск

Из каталога `2_crawler/`:

```bash
docker compose up -d --wait
uv sync --locked
uv run crawler config.yaml
```

Единственный аргумент — путь к YAML-конфигу. В `db.uri` задаётся URI MongoDB,
в `db.name` — имя базы. Примеры находятся в `config.yaml` и `config.full.yaml`.

Compose запускает одноузловой replica set `rs0`, необходимый для транзакций,
и сохраняет данные в Docker volume `mongodb-data`. Порт 27017 доступен только
через localhost; авторизация в этой локальной конфигурации отключена.
`docker compose down` останавливает MongoDB, сохраняя данные;
`docker compose down -v` **удаляет данные**. Для внешней MongoDB укажите свой URI
и используйте replica set с поддержкой транзакций.

Робот начинает с `seeds`, извлекает ссылки из HTML и добавляет их в постоянную
очередь. Загружаются только ссылки того же хоста, что и текущая страница.
Для каждого источника `include_paths` задаёт разрешённые префиксы путей
(по умолчанию `/`), а `exclude_paths` — исключённые. Исключения имеют приоритет.
Ссылки на файлы с расширениями, отличными от `.html`, `.htm`, `.php`, пропускаются;
пути без расширения разрешены. Фрагменты удаляются, дубли не создают новых заданий.

`seeds` загружаются явно, даже если не подходят под правила документов:
их можно использовать как навигационные страницы, например указатель man7.
Такие страницы обрабатываются, но не сохраняются в `documents`.
Найденные ссылки, документ и завершение задания фиксируются одной транзакцией,
чтобы при перезапуске не потерять продолжение обхода.

В коллекции MongoDB `documents` сохраняются нормализованный URL, HTML, источник и Unix timestamp.
Для каждого хоста с ожидающими заданиями запускается отдельная задача.
Разные хосты обрабатываются конкурентно, внутри одного хоста — последовательно.
Источники на одном хосте делят задачу и задержку между началами запросов.
Ожидание одного хоста не останавливает остальные.

Задержку можно переопределить для каждого источника в `sources`:

```yaml
logic:
  request_delay_seconds: 2
  timeout_seconds: 30
sources:
  - name: linux-kernel
    request_delay_seconds: 3
    seeds:
      - https://docs.kernel.org/
  - name: llvm
    request_delay_seconds: 0.5
    seeds:
      - https://llvm.org/docs/
```

`request_delay_seconds` источника заменяет общее значение из `logic`;
если поле отсутствует или равно `null`, используется общее значение.
Допускаются неотрицательные числа, включая `0`.
Для источников одного хоста применяется максимум их эффективных задержек:
они по-прежнему используют общую задачу и ограничение частоты запросов.
Для источника с несколькими хостами настройка действует на каждый из них.
Ограничения `Crawl-delay` и `Request-rate` из robots.txt могут увеличить задержку.
Интервал отсчитывается между началами запросов, включая запрос robots.txt.

Операции хранилища защищены блокировкой; завершение страницы выполняется
в отдельной MongoDB-сессии и транзакции. Выбор задания атомарен (`findOneAndUpdate`);
сетевые запросы и задержки выполняются вне блокировки. При отмене или фатальной
ошибке все задачи завершаются до закрытия соединения с базой.
Очередь хранится в той же базе: `pending` → `processing` → `done` / `failed` / `blocked`.
Успешная запись документа и завершение задания фиксируются одной транзакцией.
Повторный запуск возвращает в очередь прерванные, ошибочные и заблокированные
правилами сайта задания. Завершённые задания возвращаются после истечения
`logic.revisit_after_seconds` с последней успешной проверки (по умолчанию сутки).
Интервал 0 включает проверку при каждом запуске. Очередь подготавливается один
раз перед обходом: даже при нулевом интервале бесконечного цикла проверок нет.
Ошибочные задания повторяются один раз за запуск; число попыток и последняя
ошибка сохраняются в базе.

Обрабатываются только источники, присутствующие в текущем конфиге.
Одна база рассчитана на один запущенный процесс робота.

Фрагменты URL удаляются, query-параметры сохраняются. Принимаются только
успешные HTML-ответы. Ошибка отдельной страницы не прерывает остальные
загрузки; при наличии ошибок команда завершается с кодом 1.
Редиректы 301/302/303/307/308 добавляют целевой URL в очередь вместо
автоматического перехода HTTP-клиентом. Целевой адрес проходит обычные проверки
robots.txt и задержек, относительные ссылки разрешаются уже от него.
Переходы на другой хост и за границы источника запрещены. При перенаправлении
с HTTPS на HTTP в пределах хоста сохраняется HTTPS. Отсутствующий Location
или переход на тот же URL считается ошибкой. Циклы между уже известными URL
не приводят к повторным загрузкам в рамках одного запуска.
Валидаторы исходного URL не переносятся на целевой; предыдущая сохранённая
версия исходной страницы, если она была, остаётся в базе.

Перед загрузкой страниц робот запрашивает `/robots.txt` для соответствующей
схемы и хоста. Правила кэшируются на время запуска и проверяются для
`CourseCrawler/0.1`. Запрет сохраняется как `blocked`, без загрузки страницы.
Ответы 404/410 означают отсутствие правил, 401/403 — запрет обхода.
При сетевой ошибке, редиректе, 429 или серверной ошибке документы не загружаются,
а задания получают `failed`. Следующий запуск проверяет правила заново.
Задержка выбирается как максимум из настройки, `Crawl-delay` и интервала,
вычисленного из `Request-rate`. Разбор правил выполняет стандартный
`urllib.robotparser` с его ограничениями поддержки формата.

## Переобкачка

Успешные ответы сохраняют `ETag` и `Last-Modified` в задании. При повторной
проверке отправляются `If-None-Match` и `If-Modified-Since`, если сервер ранее
предоставил соответствующие заголовки.

- `304 Not Modified` обновляет время проверки и валидаторы, не затрагивая HTML.
- `200 OK` сравнивается по SHA-256 извлечённой из HTTP-ответа HTML-строки.
  При совпадении хеша сохранённый документ не перезаписывается.
- При изменении обновляются HTML, хеш и `fetched_at`; новые ссылки попадают
  в очередь в той же транзакции.
- `jobs.checked_at` — время последней успешной проверки;
  `documents.fetched_at` — время сохранения текущей версии текста.
- Ошибка или запрет robots.txt не удаляют предыдущую версию документа
  и не меняют время успешной проверки.

Навигационные страницы тоже проверяются повторно, даже если не включены в корпус.
Сроки проверяются при запуске, а не фоновым таймером: для периодического обхода
нужно регулярно запускать команду, например через cron.

Пока нет повторных попыток в рамках одного запуска. Сохранённый HTML не очищается
от разметки. Перед массовой загрузкой необходим пробный обход источников.

## Тесты

```bash
docker compose up -d --wait
uv run --locked pytest
```

Тесты используют подмену HTTP и реальную MongoDB из Compose. Для каждого теста
создаётся отдельная база `crawler_test_<uuid>`, которая затем удаляется.
URI можно переопределить через `MONGODB_URI` (сервер должен поддерживать транзакции).
После установки зависимостей и Docker-образа доступ к интернету не нужен. Проверяются
конфигурация, нормализация URL, сохранение и обновление документов,
HTTP-ошибки, таймауты и обработка ошибок CLI. Также проверяются восстановление
после отмены, повтор ошибочных заданий, изоляция источников и атомарность
сохранения результата. Конкурентный обход проверяется отдельно: независимость
хостов, общая задержка для источников одного хоста и отмена всех задач
с последующим восстановлением. Переобкачка проверяется с управляемым временем:
истечение интервала, условные заголовки, ответы 304, неизменный и изменённый HTML,
обновление ссылок и сохранение предыдущей версии при ошибке.

## Структура

- `src/crawler/config.py` — конфигурация и нормализация URL.
- `src/crawler/models.py` — структуры задания, HTTP-страницы и результата обхода.
- `src/crawler/storage.py` — коллекции MongoDB, индексы, очередь и транзакции.
- `compose.yaml` — локальный MongoDB replica set.
- `src/crawler/engine.py` — координация очереди и сохранение результатов.
- `src/crawler/http.py` — загрузка HTML, ожидание и кэш правил robots.txt.
- `src/crawler/sources.py` — извлечение ссылок и границы источника.
- `src/crawler/robots.py` — загрузка robots.txt и задержки из правил.
- `src/crawler/cli.py` — командная строка.
- `tests/` — автотесты.
- `data/` — локальные данные, исключённые из Git.
